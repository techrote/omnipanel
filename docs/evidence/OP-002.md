## Schema inventory and invariants

`docs/SCHEMA_CONTRACTS.md` is the full inventory. The load-bearing properties are:

- top-level records require exact integer `schema_version = 1`;
- future/unknown versions, unknown fields and unknown enum values fail closed;
- models are immutable and identity/dependency collections are bounded;
- authoritative IDs are distinct from display text and aliases;
- model identity is provider + model ID; component identity is component + contract + version;
- Single/Race/Diversity are explicit, and Race requires an explicit named Race policy;
- Stone requires independent implementation review;
- Steel requires independent implementation review, independent verification review and
  explicit user adjudication before consequential promotion;
- Steel/priceless/days/paid can be represented without a human choice but remain
  explicitly undecided until a structured decision record exists;
- provider requests default to no capability handles, no writable paths, no network,
  zero requested resources and isolation required;
- hidden acceptance gates must be master-only and require an independent evaluator context;
- gate outcomes distinguish PASS, FAIL and NOT RUN;
- only model safety state `active` is automatically schedulable; `quarantined` and
  `verboten` are fail-closed snapshots;
- normal cancellation without retained salvage must explain why salvage was unavailable;
  retained salvage requires evidence references, while emergency containment may retain none.

These are typed representation/invariant rules only. Durable migration, readiness,
compatibility negotiation, scheduling and safety-transition state machines remain owned
by later task IDs.

## Dependency rationale

Pydantic `2.13.5` is the direct OP-002 validation dependency. It provides strict closed
model validation, immutable records, typed nested contracts and JSON
serialization/schema support without introducing persistence, networking, scheduling or
provider authority. Textual `8.2.8` remains the OP-001 presentation dependency and is
not imported by domain contracts.

Direct versions remain pinned; the project does not claim a complete transitive lockfile.
CI artifacts retain the actual resolved environment per matrix job.
